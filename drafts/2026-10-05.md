## LinkedIn

**Hook**
I built a scheduler so three agents would run while I was away from my laptop. For weeks, not one of them had ever actually fired.

**Body**
The bug was almost insulting once I found it. due() read the clock, then checked a floor that only got set the first time something ran. On a fresh scheduler the floor landed a few microseconds after the exact moment I was comparing it to. Nothing was ever due.

start() in the studio hid this by setting the floor first, so the UI looked fine. But watch.py, the version meant to run with no browser open at all, called tick() directly. It printed nothing was due and exited clean. Every single run.

I only caught it by actually running the thing instead of rereading my own code for the tenth time. Fixed it by setting the floor the moment the scheduler is built, not the first time it ticks. 2299 tests pass now, up from 2277 a week earlier.

**Close**
If you have shipped something meant to run while you are not watching, how do you actually prove it ran, instead of trusting the log that says it did?

## Newsletter

**Subject**
My unattended agent never once woke up

**Body**
Three agents were supposed to run on their own while I was not at my laptop: one checking mail, one watching application deadlines, one scanning classwork. I built a scheduler for exactly that, services/scheduler, a background loop that asks each job if it is due and runs the ones that are.

For an unknown stretch of time, it is possible none of them ever ran. The bug: due() reads the clock, then compares it to a floor that only got set the first time a job actually fired. On a scheduler that had never ticked, the floor landed a few microseconds after the moment it was being measured against. Nothing was ever due, on every single check.

start() in the studio hid this completely, because it happened to set the floor before anything else. But watch.py, the no-browser mode meant to run at login, calls tick() directly. It printed nothing was due and exited clean, which looks exactly like a healthy scheduler that genuinely found no work.

The fix was one line: set the floor the moment the scheduler is constructed, not the first time it runs. 2299 tests pass now. The part I keep thinking about is that a log saying nothing to do and a log hiding a dead loop read identically unless you go and check.

**Close**
If you have ever shipped something meant to run unattended, how do you actually verify it ran. Reply, I am collecting answers.
