09_MEMORY_OPERATING_MODEL.md
Agent OS — Memory Operating Model
Version: 1.0.0
Status: Ratified
Classification: Architecture Constitution — Binding on All Memory Behavior
1. Preamble
This document derives the Memory Operating Model from the constitutional architecture established in 01_PRINCIPLES.md, 02_ARCHITECTURE.md, 03_TECH_STACK.md, 04_BUSINESS_OPERATING_MODEL.md, 05_AGENT_RUNTIME_FRAMEWORK.md, 06_AGENT_OPERATING_MODEL.md, 07_WORKFLOW_OPERATING_MODEL.md, and 08_EVENT_OPERATING_MODEL.md. It specifies how memory behaves inside Agent OS: how organizational experience is captured, validated, linked, decayed, and retrieved to enable continuous learning across autonomous businesses. This is not an implementation specification. It is the behavioral contract that all memory producers, all memory consumers, and all runtime subsystems interacting with memory must fulfill. Where this document is silent, the constitution governs. Where this document speaks, it is binding.
2. Memory Philosophy
2.1 The Organizational Experience Metaphor
Memory in Agent OS is persistent organizational experience. It is the accumulated record of what the venture studio has done, observed, decided, and felt. Memory is not a technology layer; it is the living tissue of the organization. Just as a human enterprise retains institutional knowledge through documented decisions, shared stories, and unspoken habits, Agent OS retains organizational memory through structured, attributable, and retrievable experience records. Without memory, every agent execution begins as a blank slate, every workflow repeats past mistakes, and every business loses its identity the moment its current tasks complete.
2.2 Memory vs. Storage
Storage is passive retention of bits. Memory is active, interpretable experience. A database table holding raw scrape data is storage; the distilled observation that "Competitor X lowered prices in response to supply chain pressure" is memory. Storage preserves bytes; memory preserves meaning. The Memory Operating Model governs only memory. Raw data may be stored, but it does not become memory until it has been formed, validated, and attributed.
2.3 Memory vs. Knowledge
Knowledge is validated, structured, and contextualized understanding derived from memory. Memory is the substrate; knowledge is the refined product. Memory records that "Agent A observed outcome B on Tuesday." Knowledge asserts that "Approach C reliably produces outcome B." The Memory Operating Model governs the retention and retrieval of memory. The extraction of knowledge from memory is governed by the Learning Model and the Knowledge Base. Memory may be raw, contradictory, or uncertain; knowledge must be validated and confident.
2.4 Memory vs. Events
An event is an immutable record that something occurred. Memory is the interpretive retention of that occurrence within the organization's experience. Events are the source of truth; memory is a curated, indexed, and contextualized projection of events optimized for agent consumption. If the event log is the nervous system's electrical signal, memory is the brain's lasting impression of that signal. Memory can be reconstructed from events, but it serves a distinct purpose: continuity of context across time.
2.5 Memory vs. State
State is the current condition of an entity at a point in time. Memory is the history that produced that condition. State can be derived from memory, but memory cannot be derived from state. The runtime treats memory as the authoritative record of experience and state as a transient projection. State corruption can be repaired by replaying memory; memory corruption is irreparable. Therefore, memory is guarded more strictly than state.
2.6 Memory as Competitive Moat
In an autonomous venture studio, memory is the primary competitive advantage. A competitor may replicate tools, models, and prompts. It cannot replicate the accumulated, validated, and relationship-enriched experience of a portfolio that has launched, failed, and succeeded across dozens of businesses. Memory compounds. The system must treat memory as its most valuable asset, prioritizing its preservation, validation, and availability above operational convenience.
3. Memory Mission & Permanent Objectives
3.1 Mission
The memory subsystem exists to preserve, validate, and make retrievable the complete organizational experience of the venture studio so that every agent, workflow, and business operates with the accumulated wisdom of all prior execution, subject to absolute constraints of ownership, privacy, and human sovereignty.
3.2 Permanent Objectives
The memory subsystem pursues these objectives in perpetuity, ordered by priority:
Continuity: Ensure that no agent begins a task without access to relevant prior experience. The runtime must be strictly smarter tomorrow than it is today.
Contextual Fidelity: Preserve not just what happened, but why it happened, under what conditions, and with what intent. Memory without context is noise.
Validated Recall: Distinguish between observed experience and verified truth. The system must recall confidently when evidence is strong and express uncertainty when memory is speculative.
Ownership Enforcement: Ensure that every memory entry is owned, scoped, and isolated such that no tenant, business, or agent accesses memory beyond its authorized boundaries.
Decay Discipline: Actively degrade, archive, and purge memory that has become stale, irrelevant, or legally toxic. Unbounded memory growth is a failure mode.
Cross-Business Pollination: Make anonymized, validated patterns from one business available to others within the portfolio, preventing siloing while enforcing isolation.
3.3 Objective Conflicts
When objectives conflict, the resolution order is: Human Sovereignty > Ownership Enforcement > Validated Recall > Continuity > Decay Discipline > Cross-Business Pollination. The memory subsystem may not sacrifice privacy or truth for availability.
4. Memory Identity
4.1 Identity Primitives
Every memory entry possesses an immutable identity consisting of:
Memory ID: A universally unique identifier assigned at formation, never reused, never reassigned.
Memory Type: A hierarchical classification (e.g., episodic.execution, semantic.fact, procedural.pattern) declaring the semantic role of the entry.
Schema Version: A semantic version indicating the structural contract of the entry's payload.
Timestamp: The authoritative time at which the experience occurred, distinct from formation or retrieval time.
Source Identity: The authenticated agent, workflow, event, or human that produced the memory.
Tenant ID, Business ID, Workspace ID: The isolation boundaries that own this memory.
Confidence Score: A quantitative measure (0.0–1.0) of the memory's reliability at time of formation.
Validity Period: The temporal window during which the memory is considered potentially relevant.
Lineage Reference: The immutable identifier linking this memory to its originating event or decision journal.
4.2 Identity Persistence
Memory identity persists for the statutory retention period (minimum seven years) regardless of the memory's active status. A memory entry is never anonymous. Its identity is the anchor for auditability, cost attribution, and forensic reconstruction.
4.3 Identity as Accountability Anchor
Every memory entry is attributable to a specific producer. Every retrieval, modification (via append-only correction), and access is logged against the memory's identity. The runtime does not permit anonymous or pseudonymous memory. Identity is the foundation of trust in the memory system.
5. Memory Classification
5.1 Classification by Semantic Role
Memory is organized by the role it plays in organizational cognition:
Episodic Memory: Records of specific executions, tasks, and workflow instances. "What happened."
Semantic Memory: Generalized facts, concepts, and relationships about the market, the business, and the world. "What is true."
Procedural Memory: Patterns of successful action, heuristics, and validated workflows. "How to succeed."
Relational Memory: Connections between entities, agents, businesses, and concepts. "What relates to what."
Strategic Memory: High-level decisions, mission alignments, and portfolio-level intent. "Why we chose this path."
Failure Memory: Catalogued mistakes, root causes, and remediation records. "What to avoid."
5.2 Classification by Structural Form
Atomic: Indivisible observations (e.g., a single fact, a single decision).
Composite: Aggregated summaries of multiple atomic entries (e.g., a project retrospective).
Narrative: Sequential, context-rich accounts of extended experiences (e.g., a saga execution log).
Graph Edge: Typed relationships linking two or more memory entries.
5.3 Classification by Sensitivity
Public: Contains no tenant-specific data; safe for cross-tenant visibility.
Tenant-Scoped: Belongs to a specific tenant; invisible to others.
Restricted: Contains financial, legal, security-sensitive, or personally identifiable experience; requires elevated permissions.
5.4 Classification by Persistence Model
Working: Active execution context, rapidly accessible, recoverable after agent restart.
Durable: Validated and committed to persistent organizational record.
Semantic: Indexed for associative and similarity-based retrieval.
Cold: Archived for compliance, audit, and long-term pattern mining.
6. Memory Architecture & Topology
6.1 Gateway-Mediated Access
No agent, workflow, or service accesses memory directly. All memory operations flow through the Memory Gateway, which enforces schema validation, ownership checks, tier routing, and audit logging. The Memory Gateway is the sole boundary between the runtime and the memory substrate. This ensures that memory behavior is governed uniformly, regardless of producer or consumer.
6.2 Producer-Consumer Topology
Memory producers (agents, workflows, event consumers, human operators) emit memory formation requests to the Memory Gateway. Memory consumers (agents during context hydration, review agents, governance subsystems, learning models) query the Memory Gateway for retrieval. The Gateway mediates all flow: it does not permit producers to write directly to consumers' contexts, nor consumers to scan memory without scoped queries.
6.3 Boundary Enforcement
The Memory Gateway enforces boundaries at every operation:
Tenant Boundary: Rejects cross-tenant memory access without explicit anonymization and human approval.
Business Boundary: Filters retrieval to the requesting business unless a shared workspace grant exists.
Agent Boundary: Prevents agents from accessing Private memory of other agents.
Tier Boundary: Controls which consumers may access which persistence tiers based on role and task classification.
6.4 Relationship to Event Bus and Knowledge Base
The Event Bus is the source of truth for occurrence. The Memory Gateway consumes events to form memory, but memory is not a passive mirror of the event log. It is a curated, enriched, and indexed projection. The Knowledge Base extracts from memory; memory does not contain knowledge. This pipeline is unidirectional: Events → Memory → Knowledge. Corrections flow backward as new events, not as mutations.
7. Memory Hierarchy
7.1 Tier 1: Working Memory
Working memory holds the active execution context of agents and workflows. It is ephemeral in the sense that it serves the current task, but it is durable in the sense that agent crashes or restarts must not lose it. Working memory contains session state, recent conversation turns, intermediate computation results, and active tool outputs. It is the highest-velocity, lowest-latency tier.
7.2 Tier 2: Durable Memory
Durable memory contains validated, committed organizational experience: facts, decisions, episodes, and outcomes that have passed validation and been assigned confidence scores. This tier is the primary repository of organizational history. It is structured, queryable, and causally linked. Durable memory survives business sunsets and agent retirements.
7.3 Tier 3: Semantic Memory
Semantic memory is the associative retrieval tier. It contains memory entries that have been enriched with relationship links, contextual embeddings (conceptually), and graph connections. This tier enables non-obvious discovery: retrieving memories that are not identical to the query but are experientially relevant. Semantic memory is derived from Durable memory through integration and linking processes.
7.4 Tier 4: Cold Memory
Cold memory is the archival tier. It contains aged, infrequently accessed, or legally retained memory entries. Retrieval is slower and may require human approval for bulk access. Cold memory exists for compliance, forensic investigation, and long-term organizational learning. It is never destroyed before the statutory retention period.
7.5 Tier Movement Governance
Movement between tiers is governed by lifecycle rules, not merely by time. A memory entry is promoted from Working to Durable when validated. It is promoted to Semantic when linked. It is demoted to Cold when its retrieval frequency drops below threshold and its validity period expires. Tier movement is itself a memory operation, logged and auditable.
8. Memory Lifecycle
8.1 Conception
Memory begins with an occurrence: an agent completes a task, a workflow reaches a checkpoint, a human provides insight, or an event signals a meaningful change. The conception phase identifies that an occurrence is worth remembering, as opposed to being transient computation or raw data noise.
8.2 Formation
During formation, the occurrence is captured as a structured memory entry with full identity, provenance, and initial payload. Formation does not imply validation; it implies structure. Unstructured or schema-violating captures are rejected at the Gateway.
8.3 Validation
Validation assesses the memory entry against source reliability, cross-reference consistency, schema conformance, and temporal relevance. Validation assigns the initial confidence score and validity period. Entries failing validation are quarantined for review, not committed to Durable memory.
8.4 Integration
Integration links the new memory entry to existing memory: establishing causal chains, identifying contradictions, and creating relational edges. Integration transforms isolated facts into a web of experience. An unlinked memory entry is incomplete.
8.5 Activation
Activation makes the memory entry available for retrieval by authorized consumers. Until activation, the entry exists but is invisible to agents. Activation occurs after integration and may be tier-specific (e.g., activated in Semantic tier only after graph linking is complete).
8.6 Decay
Decay is the progressive reduction of a memory entry's relevance, confidence, and accessibility over time. Decay is not deletion; it is degradation. The memory subsystem continuously evaluates whether entries remain true, relevant, and useful. Stale entries are flagged, downgraded, or moved to Cold tiers.
8.7 Disposition
Disposition is the terminal phase: promotion to a higher tier, archival to Cold, or purging per policy. Disposition is irreversible for purging and requires audit logging. Entries dispositioned to archive retain their identity and lineage indefinitely.
9. Memory States & Transitions
9.1 Canonical States
Table
State	Description
Draft	Captured but unvalidated; resides in Working tier only.
Validated	Passed validation; committed to Durable tier.
Linked	Integrated into the relational and semantic web.
Active	Regularly retrieved and referenced by agents.
Stale	Confidence decayed or validity expired; flagged for review.
Archived	Moved to Cold tier; retained but low-availability.
Purged	Destroyed per policy; identity retained in audit log only.
9.2 Transition Guards
Draft → Validated: Schema compliance, source attribution complete, initial confidence ≥0.5.
Validated → Linked: Integration process complete; at least one causal or relational edge established.
Linked → Active: Retrieval index built; no ownership conflicts detected.
Active → Stale: Validity period expired OR confidence decayed below threshold OR no retrieval for defined duration.
Stale → Archived: Human or automated review confirms irrelevance; no active dependencies.
Stale → Active: Revalidation confirms renewed relevance (e.g., cyclical market pattern).
Archived → Purged: Statutory retention period elapsed AND human or policy approval for destruction.
9.3 State Immutability
Once a memory entry enters Validated, its core identity and payload are immutable. State transitions apply to the entry's lifecycle metadata and tier placement, never to the historical record itself. A correcting entry is a new memory entry linked to the original, not a mutation.
9.4 Emergency Transitions
Bypassing normal flow (e.g., Active → Purged for legal takedown) is permitted only with Class D authority (human operator) and is logged as a constitutional exception. The original entry identity remains in the audit trail.
